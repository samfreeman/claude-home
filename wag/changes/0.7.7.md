# 0.7.7 — Voice's readable copies come first

**From:** 0.7.6
**Date:** 2026-10-29

The readable-copy rule (0.7.1) had voice write each `.html` and then a sibling `.html.md`.
But the direction matters. Voice can turn an `.html.md` into its `.html` (swap two characters
back), and it can't do the reverse, because it can't read the `.html`. An edit made straight
to an `.html` is invisible to voice and easy to lose.

## What changed

In `wag/workflows/poc.md` and `/wag:poc`'s non-negotiables:

- **The `.html.md` is voice's source.** For every new page and every edit, voice writes or
  edits the `.html.md` first, then decodes it into the `.html`. It never edits an `.html`
  directly. If the two ever disagree, the `.html.md` is right.
- **The POC's `index.html` is named** alongside the mockups and the docs renders.
- **Step 5 builds `index.html` this way.** The starter's encoded block (from the starter's
  `index.html.md`, without its note and code fence) becomes the project's
  `.wag/poc/index.html.md`, and `index.html` is decoded from it. The starter's `data.js.md`
  isn't copied: `data.js` has no tags, so it needs no copy.
- Steps 3 and 5's reminders say "written first".

## Reconcile a 0.7.6 project

- **Detect:** a project whose `.html` files were edited after their `.html.md` siblings.
- **Reconcile:** CC regenerates each stale sibling from its `.html`. Voice can't, because it
  can't read the `.html`. From then on, voice edits the `.html.md` first.
- **Verify:** every `.html` decodes exactly from its `.html.md`.
