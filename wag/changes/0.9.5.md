# 0.9.5 — Readable copies by read-back; the brand mark; the POC notice's content

**From:** 0.9.4
**Date:** 2026-10-29

Follow-up to 0.9.4, from VÖROOM's POC. Voice's Dropbox reader turned out to strip tags from
some file types but not others: a JavaScript file full of markup came back intact.

## What changed

- **`wag/workflows/poc.md`, readable copies.** HTML files always have a `NAME.md` sibling.
  Any other file gets the read-back test when voice first writes it: if it comes back exactly
  as written, it has no sibling and voice edits it directly; if anything was stripped, it gets
  a sibling, written first. This replaces 0.9.4's rule that the `scripts/` parts need
  `.js.md` siblings. `shell.js` is copied from the starter without a sibling, and "Set the
  menu" edits it directly. `.vercelignore` still excludes `*.html.md` and `*.js.md`. The
  starter's own encoded copies (in the Dropbox mirror) are unchanged.
- **`wag/workflows/poc.md`, splitting the shell:** the example is generic (card, compose,
  search); no project is named.
- **The brand mark.** Step 3 first checks the brand for a logo mark, a wordmark, a favicon and
  an icon style; Step 4 records in Architecture's Design direction what exists, or that none
  does. Step 6: the logo is one `logo()` in `shell.js`, used by the sidebar and filling any
  element marked `data-logo`; the favicon is the same SVG, added by `shell.js` as a `data:`
  link. With no vector art, the mark is an inline SVG marked `PLACEHOLDER`, and Architecture
  says so.
- **The POC notice** says what this is and isn't, why it exists, that sign-in is simulated
  and the data made up and nothing saved or sent, and links to Project Documents with
  `data-action="open-docs"`, which skips sign-in, with a note saying so. How it looks is
  worked out with the user.
- **Step 6** says up front to expect going back and forth with the user on look and layout.
- **Starter (`wag/templates/poc/`):** `shell.js` has `MARK`, `logo()`, the favicon, the
  `data-logo` fill and the `open-docs` action, all in its markup contract. `pages/index.html`
  has the logo in its header (`data-logo="tagline"`) and the new notice. `data.js` has
  `app.tagline`.

## Reconcile a 0.9.4 project

- **Detect:** `.js.md` siblings (such as `shell.js.md` or `scripts/*.js.md`); a `shell.js`
  with no `logo()`; a landing notice with no Project Documents link.
- **Reconcile:**
  - Readable copies: give each non-HTML file with a sibling the read-back test. Delete the
    sibling of any file that comes back intact, and edit that file directly from then on.
  - Logo: add `MARK`, `logo()`, `addFavicon()`, the `data-logo` fill and the `open-docs`
    action from the starter's `shell.js`, with the project's own mark if it has one. Use
    `logo()` in the sidebar and `data-logo` in the landing header. Record the brand in
    Architecture's Design direction.
  - Notice: rewrite it to say what the starter's says, in the project's look.
- **Verify:** the favicon shows the mark; the notice's link opens Project Documents from the
  signed-out landing page.
