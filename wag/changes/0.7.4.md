# 0.7.4 — The POC's docs show the design: diagrams, tables, charts

**From:** 0.7.3
**Date:** 2026-10-28

The POC's Project Plan & Status page shows the PRD and Architecture as HTML. Step 5 only
pointed at the `/wag:html-*` procedures, so a plain prose-and-tables render met the letter of
it. The point of those docs is that a reader sees the design: schemas, data flows, the user
flow. This release makes that the requirement.

## What changed

In `/wag:poc` Step 5 (`wag/workflows/poc.md`), a new *The docs renders* section:

- **Diagrams are required, as inline SVG**, wherever the doc has the content.
  - **Architecture:** an entity-relationship diagram of every schema, the main data flows and
    integrations, a layer or host diagram, and a sequence diagram per multi-actor flow.
  - **PRD:** the user flow end to end, a map of the UI pages and menu, and the scope.

  The set is proposed and each diagram reviewed with the user, per the procedures.
- **Tables are HTML tables** with the shell's styling.
- **Numbers become charts:** inline SVG bar or line charts for viability's cost and capacity
  figures, timelines and volumes. No chart library, so the file stays self-contained.
- **No git, so the existing file is the baseline on a re-render.** Diagrams in an unchanged
  section are kept, and only changed ones are re-reviewed.
- **Self-contained and theme-matched**, so the downloaded file looks like the POC.

## Reconcile a 0.7.3 project

- **Detect:** a POC whose `poc/docs/*.html` lack the required diagrams.
- **Reconcile:** re-render them to the new bar, keeping any diagram already approved.
- **Verify:** each render opens offline and shows its diagrams, and Architecture's ERD covers
  every schema.
