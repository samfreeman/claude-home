# 0.11.0 — POC comments, the development-only look, and a top bar

**From:** 0.10.2
**Date:** 2026-10-30

What the VÖROOM POC added for its reviewers, made the POC command's standard for every new
POC: a reviewer leaves a comment on whatever page they're on, and it reaches the owner as a
file in Dropbox. VÖROOM is the reference, not changed by this release. Also records who does
what: voice makes every POC change; CC does only what voice can't.

## What changed

- **Starter `scripts/comments.js`** (new): the Comment button and dialog. The button sits at
  the end of the top bar, beside Sign in on the landing page, or fixed top right. The dialog
  names the page, picks the reviewer's name (remembered in the browser), and posts the name,
  the page's full address and the text to `/api/comment`.
- **Starter `api/comment.js`** (new): the Vercel function. It trades the refresh token for an
  access token and writes one Markdown file per comment into the project's Dropbox app folder,
  `/Apps/<project>-poc/`.
- **Starter `shell.js`:**
  - The development-only look, `data-dev`: a thin, muted, dashed pink outline. The menu's
    Development section wears it, headed "Development only".
  - A sticky top bar over every signed-in page, marked `data-topbar`, holding the light/dark
    toggle (moved from the sidebar footer). The sidebar is sticky too.
  - Loads `scripts/comments.js` with the loader from Step 6's shell split; parts added later go
    before it.
  - The markup contract adds `data-dev`, `data-topbar` and `data-action="open-comment"`.
- **Starter `data.js`:** a development-only `poc` block, `{ owner, reviewers: [{ name,
  initials }] }`, kept apart from the app's fake data. Voice fills it in at Step 6.
- **Starter `pages/index.html`:** the POC notice no longer says nothing is sent. It says
  only the comments left with the Comment button are sent, to `{{poc.owner}}`.
- **Starter `pages/project-documents.html`:** `--top-bar` is `3.5rem`, the new top bar's height.
- **`wag/workflows/poc.md`:**
  - *Who does what*: voice does everything it can, including every POC change. CC does only
    what voice can't (deploying, running servers like `vercel dev`, the handoff, changing the
    WAG commands). "When the user works in CC alone, CC does the voice steps too" is gone.
    New Rule 7 says the same.
  - Step 6: the starter copies `scripts/comments.js` and `api/comment.js` directly, like
    `shell.js`; sets the comment names; and has new sections *Development only stands out*
    and *Comments*. The standard chrome adds the top bar and comments. The POC notice's
    required content changes as above. The development-only pink is the one exception to
    theme tokens only.
  - Step 7: the comments setup, once per project: the Dropbox app (scoped, app folder,
    `files.content.write` only, never full Dropbox), the refresh token, and the three Vercel
    environment variables for Production and Development, with the user handling the secrets
    and CC checking `vercel env ls`. After every deploy, `GET /api/comment` answers 405. Running
    locally under `vercel dev`, with `VERCEL_CLI_USE_NATIVE_BINARY=0` while CLI 65.x's
    native binary can't install builders here.
  - Rule 3: no backend except the development-only comments function. What's development
    only isn't ported at the handoff.
  - The folder tree adds `scripts/comments.js` and `api/comment.js`.
- **`commands/wag/poc.md`:** the same split of who does what, the backend exception, and the
  Dropbox access rule.

## Reconcile a 0.10.x project

- **Detect:** `.wag/poc/` has no `api/comment.js`, or `shell.js` has no `data-topbar`.
- **Reconcile:** these are POC changes, so voice makes them; CC does the setup.
  - Voice copies `scripts/comments.js` and `api/comment.js` from the starter; adds `data-dev`,
    the Development only section and the `data-topbar` top bar to `shell.js` (in the
    project's own look) and loads `comments.js` last; adds the `poc` block to `data.js`; and
    rewords the POC notice.
  - CC walks the user through Step 7's comments setup, then redeploys.
- **Verify:** every page shows the Comment button in the development-only look; the deployed
  `/api/comment` answers a GET with 405; one comment sent from the site lands in
  `/Apps/<project>-poc/`.
