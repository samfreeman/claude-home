# 0.2.0 — Versioning arrives

**From:** 0.1.0 (pre-versioning — no project was ever stamped)
**Date:** 2026-06-01

First link in the chain. This is the version where wag2 started stamping projects and carrying a migration path, so every project created at or before 0.1.0 is unstamped by definition.

## What changed

- `.wag/state.json` now carries a `wag_version` field. `/wag:init` (Phase E) stamps it from `wag/config.json` (`version`).
- `/wag:update` introduced — the one command that owns versioning: reads a project's stamp, walks the change-record chain (this directory) to latest, and reconciles drift advisorily.
- `wag/changes/` introduced as the home for these per-version links.

## Reconcile a pre-0.2.0 project

The only on-disk change *this* version forces is the stamp itself. (Structural drift from earlier, unrecorded eras — backlog numbering, infra PBI, missing dirs — is handled by `/wag:update`'s strategy catalog S1–S7, not by this link.)

- **Detect:** `.wag/state.json` has no `wag_version`.
- **Reconcile:** add `wag_version` set to the current `config.json` version. In practice this happens as `/wag:update`'s final stamping step (Phase 4), after any other catalog reconciliation.
- **Verify:** `.wag/state.json` carries `wag_version` equal to latest.
