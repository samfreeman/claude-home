# 0.7.0 — `/wag:poc`: a working showcase before the real build

**From:** 0.6.0
**Date:** 2026-10-28

0.6.0 put static mockups and screenshots into init so a PRD could carry a picture of every
page. Grilling it showed the real goal is bigger: something business people can **click
through** before anything is built, with the docs inside it. Words plus pictures aren't
enough for that. So the mockups leave init and become part of a new command, `/wag:poc`.
It ends in a running HTML showcase on a link, and once that's approved it hands off to the
real Next.js build. Init goes back to what it was, keeping only 0.6.0's viability step.

## What changed

- **New command: `/wag:poc`** (`commands/wag/poc.md` → `wag/workflows/poc.md`). It's the
  alternative to `/wag:init`; a project runs one or the other.
  - **Voice gets the project to a working HTML site**, and CC deploys it and does the
    handoff. Every step is marked Voice or CC, and voice reads the files from the
    claude-home copy in Dropbox.
  - **It lives in Dropbox with no git** until approval.
  - **The order:**
    1. Pick up wherever the project already is (an existing PRD is checked, not redone).
    2. Init's intake (A).
    3. Init's viability (B1).
    4. **Mockups:** 4–5 looks, each a landing hero plus a few signed-in pages covering the
       app's kinds of page.
    5. Init's research and Architecture (B2), with the chosen look and a `theme.css`.
    6. **The POC.**
    7. **A Vercel production deploy**, to a public, unlisted, `noindex` URL.
    8. **Approval** (`state.json` `poc: approved`).
    9. **The handoff:** copy `.wag/` into `~/source/<project>`, `/wag:create-nextjs`, the
       theme from `theme.css`, a backlog whose first PBI ports the POC on its fake data,
       then finalise.
- **The POC** (`wag/templates/poc/`: `index.html`, `theme.css`, `data.js`, `vercel.json`) is
  plain HTML with Tailwind from the CDN, no build step and no backend.
  - Every PRD route is a hash-routed section, with working links, the user flow and
    simulated sign-in.
  - It has one fake data set, seen by one user.
  - Every POC has the same signed-in chrome: sign out, the light/dark toggle, and a
    Development section with **Project Plan & Status**. That's an accordion: the PRD and
    Architecture as self-contained HTML renders, each downloadable, plus a Backlog item that
    says it comes after approval.
  - It's written in the real app's vocabulary (theme tokens, shadcn `data-slot`, Lucide), so
    the real app ports it rather than redesigning it.
- **`/wag:add-theme` installs from `.wag/poc/theme.css`** when it exists: by preset name, or
  by copying a custom theme's blocks into `globals.css`.
- **`/wag:add-db` gains seed and reset.**
  - It adds `seeds/seed.ts` and the `db:seed` and `db:reset` scripts (drop, migrate, seed).
  - The guard runs them only when `DB_ENV` is `dev` or `qa`, never production.
  - After a POC handoff, the seed is the POC's fake data set.
- **Init reverts to before 0.6.0, except viability.** Phase B is now B1 viability (go/no-go),
  then B2 research and Architecture. The mockup step is gone, along with
  `wag/references/mockups.md`, `wag/templates/mockup.html` and `scripts/mockup-shots/`.
- **The PRD manifest's item 8, UI pages,** is now the route table and menu only, with no
  screenshots. The POC shows the pages itself.
- **`md2docx.py` keeps 0.6.0's images, tables and lists.** No mode calls it now that the POC
  shows the docs, but the Explorer "Convert to Word" entry still uses it.

## Reconcile a 0.6.0 project

- **Detect:** `wag_version` is 0.6.0.
- **Reconcile:**
  - **A PRD with per-route screenshots** still conforms: item 8 asks only for the route table
    and menu, so the image subsections can stay or go.
  - **A project with `.wag/mockups/`** from 0.6.0 can keep it as a record. Nothing reads it.
  - **A project that wants a POC** runs `/wag:poc`. It picks up from the existing docs, and
    its round-one looks go in `.wag/mockups/option-N.html`.
  - **A project with a database** that wants seed and reset adds the four files and three
    scripts from `/wag:add-db`.
- **Verify:** `/wag:adr` pre-flight passes the PRD's UI pages item on the route table alone.
