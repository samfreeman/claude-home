# 0.5.0 — One house UI standard

**From:** 0.4.1
**Date:** 2026-10-27

Every WAG web app should ship UI at the same quality, but the standard lived only in a
kwiki page and in the projects built to it — each new project copied it into its own docs
by hand, or didn't get it at all. `/wag:init` said nothing about design. This release
makes the standard part of WAG: one canonical reference, a required Architecture section
that states how a project meets it, and an init step that writes that section.

## What changed

- **New canonical reference** — `wag/references/ui-standard.md`. Foundation for every
  page (shadcn/ui components, one theme in light and dark from the tweakcn tokens, theme
  follows the browser then remembers the user's toggle, reduced-motion respected,
  1/2/3 responsive grid); the landing-page standard in full (section order, visual
  identity, CTAs, motion timings, tooling choice); and signed-in pages held to the same
  bar with restrained motion, the details still open. Every mode points at it; none
  restates it.
- **Architecture states it.** `wag/templates/architecture.md` gains an eighth
  required-content manifest item — *Design direction* — plus a suggested section: builds
  to the standard, the brand (tweakcn theme), deliberate departures and why. "n/a" for a
  project with no web UI.
- **INIT writes it.** The init workflow's Phase B writes the `Design direction` section
  and settles the brand with the user, and a web app with a UI ships the theme layer in
  ground 0 (the standard's light/dark toggle depends on it).
- **`/wag:add-theme` installs the toggle.** It used to stop at the provider and suggest a
  toggle; it now creates `ThemeToggle` (shadcn ghost icon button, flips `resolvedTheme`,
  next-themes persists the choice, hydration-safe icon swap via `dark:`), places it in
  the existing navbar/header, and adds `suppressHydrationWarning` to `<html>`, which
  next-themes requires.

## Reconcile a 0.4.1 project

This adds a **new required-content item**, so a web project's Architecture needs a small
on-disk addition.

- **Detect:** `wag_version` < 0.5.0. Symptom: `/wag:adr` pre-flight flags template drift —
  "Design direction" manifest item unanswered.
- **Reconcile:** add a `Design direction` section to `.wag/docs/Architecture.md` via
  `/wag:docs` (versioned + changelogged): it builds to the UI standard, its brand, and any
  departure with its reason. If the project already has its own design notes, fold them
  in as departures rather than restating the standard. A project without the theme layer
  adds it with `/wag:add-theme`; a project that already has it but no toggle takes the
  command's Steps 6.3–8 (`suppressHydrationWarning`, `ThemeToggle`, placement). A project with no web UI answers "n/a".
- **Verify:** `/wag:adr` pre-flight passes the item; UI PBIs are reviewed against the
  standard in `/wag:rvw`.
