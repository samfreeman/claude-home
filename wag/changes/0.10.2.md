# 0.10.2 — The deploy keeps Vercel's token off the site

**From:** 0.10.1
**Date:** 2026-10-30

Seen on VÖROOM's first deploy: `vercel link` wrote `.wag/poc/.env.local` (a Vercel access
token) and `.wag/poc/.gitignore` into the POC folder. Vercel doesn't skip `.env.local` by
default, so the next deploy would have published the token on the open site. CC deleted both
by hand before deploying; now the deploy step does it every time.

## What changed

- **`wag/workflows/poc.md`** (Step 7): after linking, CC deletes `.wag/poc/.env.local` and
  `.wag/poc/.gitignore`, before every deploy. `.vercelignore` must also hold `.env*`.
- **Starter `.vercelignore`:** adds `.env*`, as a backstop.

## Reconcile a 0.10.1 project

- **Detect:** `.wag/poc/.env.local` or `.wag/poc/.gitignore` exists, or `.wag/poc/.vercelignore`
  lacks `.env*`.
- **Reconcile:** delete the two files and add `.env*` to `.vercelignore`. If a deploy already
  went out with `.env.local` in it, redeploy, and treat the token as exposed: it's a
  short-lived token, but check it has expired.
- **Verify:** `https://<project>-poc.vercel.app/.env.local` returns 404.
