# 0.9.4 — The POC shell can split into scripts/; no READMEs in .wag/

**From:** 0.9.3
**Date:** 2026-10-29

From VÖROOM's POC: its `shell.js` grew too big for voice to write in one call, so it was split
by kind of thing into `.wag/poc/scripts/`. The workflow now says how, and when.

## What changed

- **`wag/workflows/poc.md`** (Step 6): *Splitting the shell*. Past about 10 KB, `shell.js`
  splits into `.wag/poc/scripts/`, one file per kind of thing. `shell.js` stays at the POC
  root with storage, theme, the menu, the top bar, page rendering and sign-in, and loads the
  parts itself, in order, right after itself. Pages still load only `../shell.js`. Its
  opening comment lists the parts.
- **`wag/workflows/poc.md`** (the readable-copy rule, *Where it lives*, Step 6's readable
  copies): every part in `scripts/` that holds markup has its `NAME.js.md` sibling, written
  first. `.vercelignore` already excludes `*.js.md`.
- **`wag/workflows/poc.md`** (*Where it lives*): no READMEs anywhere in `.wag/`. It's code
  that's copied into the repo at the handoff, not part of the `/Claude` README system.
- The starter's `shell.js` is unchanged; a POC splits only when it needs to.

## Reconcile a 0.9.3 project

- **Detect:** a `.wag/poc/shell.js` well past 10 KB, or any `README.md` under `.wag/`.
- **Reconcile:** split the shell as Step 6 describes (each part's `.js.md` first, then decode;
  list the parts in `shell.js`'s opening comment). Delete any README under `.wag/`.
- **Verify:** every page still opens from disk with its shell intact, and no page's head
  changed.
