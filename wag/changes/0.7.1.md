# 0.7.1 — Voice can read back the HTML it writes

**From:** 0.7.0
**Date:** 2026-10-28

Voice reads Dropbox through a fetch tool that strips every HTML tag, even inside a Markdown
code fence. In the first `/wag:poc` run on VÖROOM it could write mockups but not read them
back: no `<head>`, no classes, no attributes, only the visible text. This release gives every
`.html` a readable twin.

## What changed

- **The readable-copy rule** (`wag/workflows/poc.md`, Who does what; named again in Steps 3
  and 5 and in `/wag:poc`'s non-negotiables).
  - Every time voice writes or edits an `.html` under `.wag/mockups/` or `.wag/poc/` (every
    mockup option, the chosen one included, `index.html` and the docs renders), it also
    writes `<name>.html.md`: the same source with every `<` written as `‹` (U+2039) and
    every `>` as `›` (U+203A).
  - The pair is rewritten together on every edit.
  - Voice reads the sibling, turns `‹›` back into `<>`, and writes both files.
- **`.vercelignore`** in `wag/templates/poc/` keeps `*.html.md` off the deployed site, and
  Step 6 checks that it's there before deploying.
- **The claude-home starter** gets its readable copies from the sync instead
  (`scripts/sync-dropbox.sh` → `scripts/readable-copies.mjs`, already in place). Every
  `.html` and `.js` under `wag/templates/` has a generated `.md` twin in Dropbox.

## Reconcile a 0.7.0 project

- **Detect:** `wag_version` is 0.7.0 and `.wag/mockups/` or `.wag/poc/` holds `.html` files
  without `.html.md` siblings.
- **Reconcile:** create the missing siblings once. Voice can't, because it can't read the
  `.html` files, so CC writes them, each verified to decode to its original byte for byte.
  Copy `.vercelignore` into `.wag/poc/` if the POC folder exists. From then on, voice keeps
  them current.
- **Verify:** voice can read every page's markup back through the `.html.md`.
