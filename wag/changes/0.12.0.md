# 0.12.0 — Voice uses db4cv; readable copies are retired

**From:** 0.11.0
**Date:** 2026-11-03

Voice now has its own Dropbox connector, db4cv (`mcp-servers/dropbox`). It reads files byte
for byte, HTML included, and edits them in place against the rev it read. The built-in
Dropbox connector stripped anything tag-like and couldn't edit, so the readable copies (the
`NAME.md` siblings with less-than and greater-than written as U+2039 and U+203A) existed only
to work around it. They're gone, and so is the encoding of the claude-home mirror.

## What changed

- **`commands/wag/poc.md` and `wag/workflows/poc.md`:** a new non-negotiable and a new
  Dropbox rule. Voice uses db4cv for every Dropbox file, never the built-in connector. If
  db4cv isn't available, voice stops and says so rather than falling back. Reads are exact;
  edits go in place with the rev from the last read, and a stale rev fails without writing.
- **The readable-copy rule is gone,** with everything that hung off it: no `NAME.md` sibling
  for any HTML file or any other file, no read-back test, no write-the-sibling-first. Mockups
  (Step 3) and pages (Step 6) are written and edited directly. The folder tree and the
  docs-copies rule drop their sibling notes.
- **Step 6, the starter:** every starter file is copied as is: the root `index.html`, the
  pages, `shell.js`, `scripts/comments.js`, `api/comment.js`, `data.js`, `vercel.json` and
  `.vercelignore`. No encoded blocks to decode.
- **Step 7 and the starter's `.vercelignore`:** it holds `.env*` only. Nothing makes `*.html.md`
  or `*.js.md` files any more.
- **`scripts/sync-dropbox.sh`:** the Dropbox copy of claude-home is an exact copy of `dev`.
  `scripts/readable-copies.mjs` is removed, so Markdown there keeps real angle brackets and
  the templates get no `NAME.md` copies. The next sync deletes the old encoded copies from
  the mirror. The standing rule that tracked Markdown never contains U+2039 or U+203A goes
  with it.
- **db4cv's server instructions** tell any model to use it for Dropbox files under `/Claude`
  rather than any other Dropbox connector.

## Reconcile a 0.11.x project

- **Detect:** `NAME.md` siblings under `.wag/`: `*.html.md` in `mockups/`, `poc/` or
  `poc/pages/`, or `*.js.md` anywhere in `poc/`.
- **Reconcile:** these are POC changes, so voice makes them, through db4cv.
  - For each sibling, read it and the file beside it. Decode the sibling (U+2039 back to
    less-than, U+203A back to greater-than). If it doesn't match the file exactly, the
    sibling is right under the old rule: overwrite the file with the decoded sibling. Then
    delete the sibling.
  - Set `.wag/poc/.vercelignore` to `.env*`.
  - From then on, edit every file directly.
  - CC redeploys if the POC is deployed and any file changed.
- **Once, for the user:** turn off the built-in Dropbox connector in claude.ai, so voice can
  only reach Dropbox through db4cv. CC runs `scripts/sync-dropbox.sh` after pushing this
  release, so the mirror drops its encoding.
- **Verify:** no `*.html.md` or `*.js.md` left under `.wag/`; a page read through db4cv shows
  its markup; the deployed site still matches the files.
