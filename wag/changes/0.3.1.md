# 0.3.1 — One definition of a valid doc

**From:** 0.3.0
**Date:** 2026-06-10

Init authored free-form narratives; `/wag:adr`'s pre-flight demanded literal template headings. The system's own happy path manufactured the drift its own pre-flight halted on — every grill-authored project hit the wall on its first `/wag:adr` (surfaced by gigger, inbox #60).

## What changed

- **Each narrative template now opens with a required-content manifest** — a comment block in `wag/templates/prd.md` and `wag/templates/architecture.md`. It is the single definition of a valid PRD / Architecture doc: the doc conforms when every manifest item is *answered somewhere*, any headings, prose fine. The template's headings are demoted to a suggested starting shape.
- **Two doc classes, two conformance rules.** Narrative docs (PRD, Architecture) check by manifest content. Record docs (epics, PBIs) keep strict template shape — commands parse them positionally.
- **All commands point at the manifest, none restate it.** `/wag:adr` pre-flight checks manifest items; the init workflow (Phases A and B) verifies the manifest before each doc is presented for approval — docs leave init ADR-ready; `/wag:hadr` and `/wag:update` (S6) defer to the same rules. Changing the standard = editing one template file.

## Reconcile a 0.3.0 project

No on-disk change is forced — project docs are not touched.

- **Detect:** `wag_version` < 0.3.1. A project previously halted on PRD/Architecture heading-shape drift is the symptom this fixes.
- **Reconcile:** nothing to apply; re-run the halted command. PRD/Architecture now conform if their content answers the manifests.
- **Verify:** `/wag:adr` pre-flight passes on grill-authored narrative docs whose content is complete; it still halts on genuinely unanswered manifest items and on epic/PBI shape divergence.
