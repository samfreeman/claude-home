# 0.4.0 — One ubiquitous language per project

**From:** 0.3.1
**Date:** 2026-06-19

A project should speak one language: **one name per referent**, everywhere — docs,
contract/interfaces, data model, and code. Bounded contexts (with "context maps"
translating one referent's many names) earn their keep only when two real languages are
*forced* to coexist — non-converging teams, an external/legacy system, or a model too
large to hold unified. A solo-author / single-system / self-owned-contract project has no
such forcing function, so introducing them is imported ceremony that invites naming
drift. This release makes the ubiquitous language a first-class, conformance-checked part
of every project and threads it through every mode. (Surfaced by the wag3 Architecture
collapse of a "three bounded contexts + context maps" framing back to one language.)

## What changed

- **New canonical reference** — `wag/references/ubiquitous-language.md`: the principle,
  the forcing-function test for bounded contexts, and the rule that a module/import seam
  is enforced by code, not by a second vocabulary (a package boundary is not a
  bounded-context boundary). Every mode points at it; none restates it.
- **Architecture defines it.** `wag/templates/architecture.md` gains a sixth
  required-content manifest item — *Ubiquitous language* — plus a suggested `Ubiquitous
  language` glossary section. The Architecture doc's section is the project's authority on
  domain terms.
- **INIT discovers it.** `wag/references/questioning.md` adds "the language" as an area to
  explore (capture domain vocabulary, one name per referent); the init workflow captures
  terms at intake (Phase A) and **crystallises Architecture's Ubiquitous language section**
  in Phase B.
- **Every mode uses it.** `/wag:docs` authors in the terms and maintains the section;
  `/wag:adr` designs in them (new referent → extend the section; synonym → snag
  candidate); `/wag:dev` names `src/`/`tests/` in them (Architect + CQ check); `/wag:rvw`
  reviews whether the code speaks the language (under Architecture conformance);
  `/wag:tri` treats naming drift as a defect class and reconciles it.

## Reconcile a 0.3.1 project

Unlike 0.3.1, this adds a **new required-content item**, so a project's Architecture may
need a small on-disk addition.

- **Detect:** `wag_version` < 0.4.0. Symptom: `/wag:adr` pre-flight flags template drift —
  "Ubiquitous language" manifest item unanswered — on an Architecture with no such section.
- **Reconcile:** add a `Ubiquitous language` section to `.wag/docs/Architecture.md` — the
  core domain terms, one name per referent (a glossary table is enough). Drive it via
  `/wag:docs` (Architecture edit, versioned + changelogged). If the existing docs/code
  carry synonyms for one referent, reconcile them to a single term as part of the same
  pass (a `/wag:tri` naming-drift resolution).
- **Verify:** `/wag:adr` pre-flight passes once the section answers the manifest item;
  new code is reviewed against the section in `/wag:rvw`.
