# 0.4.1 — The scaffold checks the host Node

**From:** 0.4.0
**Date:** 2026-09-03

The baseline test toolchain (`vitest@5`, `jsdom@30`) declares a Node floor of 22, while
Next only needs 20.9. On a host running Node 20, `/wag:create-nextjs` installs cleanly
(pnpm treats `engines` as advisory), `dev`, `build` and `lint` all pass, and nothing
surfaces the mismatch until the first `pnpm test` — which fails at worker startup in every
file. Surfaced as vorsann SNAG-001, the first project on that machine to run its unit
suite.

## What changed

- **`/wag:create-nextjs` Phase 1 gains a host Node pre-flight.** `node --version` runs
  before detection; a major below 22 stops the command and tells the user to move the host
  to the current LTS before scaffolding. Older test dependencies are never pinned to fit
  the host — the house baseline is one version set.
- **`/wag:create-nextjs` Phase 3 pins the floor mechanically.** The scaffold writes
  `engines.node: ">=22"` into `package.json` and `engine-strict=true` into `.npmrc`, so a
  later install on an older host fails at install time, not at the first test run.

## Reconcile a 0.4.0 project

No template or manifest change, so no on-disk drift is flagged. Optional hardening for an
existing project:

- **Detect:** `package.json` has no `engines` field, or `pnpm test` fails at worker startup
  with `webidl.util.markAsUncloneable is not a function`.
- **Reconcile:** move the host to Node 24 LTS, `pnpm install --force` to rebuild native
  binaries, then add the `engines` field and `.npmrc` as above. Note the floor in
  `Architecture.md > Tech stack` (versioned + changelogged).
- **Verify:** `node --version` reports 22 or later and `pnpm test` runs every file.
