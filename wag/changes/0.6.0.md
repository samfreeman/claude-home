# 0.6.0 — A picture of every page before anything is built

**From:** 0.5.0
**Date:** 2026-10-28

A WAG PRD described its pages in words only. Nobody saw the app until it was built, and
flow problems surfaced in code. Sam sends stakeholders the PRD as a `.docx`, and its words
had nothing to make them obvious. This release adds a mockup step to init: a viability
gate first, then the pages drawn to the house UI standard, then a screenshot of every
route embedded in the PRD. md2docx learns to carry those images into Word, along with the
tables and lists PRDs already use.

## What changed

- **Init's Phase B splits in three.**
  - **B1 Viability** asks whether it can be built, on what platform and tier, what the hard
    unknowns are and what it roughly costs, and ends in a go / no-go.
  - **B2 Mockups** runs for web UI only.
  - **B3** is the rest of the research plus Architecture and the baseline, as before.

  Nothing is mocked up before viability says go, and Architecture comes after the mockups
  have shaken out the flow.
- **New canonical reference: `wag/references/mockups.md`.** It is the B2 procedure, with
  each step split into a voice part and a CC part (voice can read and write `.wag/` in
  Dropbox and render HTML, but can't run commands or take screenshots).
  - The order: Design direction first, then 4–5 looks of one representative signed-in
    page, then a pick and tweaks, then every route in the PRD's UI pages table plus the
    landing page, then screenshots, then `PRD.docx`.
  - Voice fixes the PRD in the same session when a mockup exposes a flow problem.
  - The UI standard and Architecture's `Design direction` are the mockups' inputs;
    Design direction stays in Architecture and now also records the chosen look.
- **`.wag/mockups/`**: `options/option-N.html` (round one), `mockup.html` (every route,
  static, one `data-route` section each, with a visible route label between them),
  `screens/` (PNGs).
- **New template: `wag/templates/mockup.html`.** The starter every mockup builds from: Tailwind
  via CDN, the tweakcn theme's CSS variables for light and dark, shadcn-styled controls,
  and the markup contract (`data-route`, `data-state`, `data-page`, `data-landing`,
  `data-review`).
- **New script: `scripts/mockup-shots/`.** `node ~/.claude/scripts/mockup-shots/shots.mjs
  .wag/mockups/mockup.html` screenshots each route, and each landing-page section
  separately.
  - It runs Playwright at a 1024px width, in light mode by default (`--dark` gives a dark
    set), with reduced motion, and hides the review chrome.
  - It prints the PRD's linked-image line for every PNG.
  - It needs a one-time `npm install` and a browser download (see the reference).
- **PRD gains an eighth manifest item, *UI pages*** (web UI only), plus a suggested
  section. It is a route table with descriptions, then one subsection per route holding
  `[![<page name>](<png path>)](<html path>)`. "n/a" for a project with no web UI.
- **`md2docx.py` grows up.** It is still stdlib-only and everything it did before still
  works. New:
  - **Images:** PNG and JPEG, scaled down to fit 6.5in with the aspect ratio kept and never
    scaled up, with the alt text as a caption. A linked image embeds the image and drops
    the link, the same as text links.
  - **Pipe tables:** header row repeated across pages, `:--:` alignment, `\|` escapes.
  - **Numbered lists:** Word's own numbering (`numbering.xml`) instead of typed digits.
  - **Nesting:** bullets and numbers, mixed, up to nine levels.
  - Also fixes the inline-code font attribute.
- **`ui-standard.md`'s INIT row and `/wag:init`** now name the B1 → B2 → B3 order.

## Reconcile a 0.5.0 project

This adds a **new required-content item** to the PRD, so a web project's PRD needs an
on-disk addition, and its pages need drawing.

- **Detect:** `wag_version` < 0.6.0. Symptom: `/wag:adr` pre-flight flags template drift
  — "UI pages" manifest item unanswered — on a web project's PRD.
- **Reconcile:**
  - **Web project:** run the mockup procedure in `wag/references/mockups.md` against the
    current PRD.
    - Step 1 reviews the existing `Design direction` rather than writing it fresh.
    - Steps 2–4 build the options, the pick and every route; fix any flow problem they
      expose in the PRD via `/wag:docs` (versioned + changelogged).
    - Step 5 turns the PRD's route list into the UI pages section, a table plus a linked
      image per route.
    - Steps 6–7 take the screenshots and build `PRD.docx`.
    - Record the chosen look in `Design direction`.
  - **Project still in init:** pick up at the new phase that matches where it is. A
    project past research but without mockups runs B2 before going further.
  - **No web UI:** answer the item "n/a".
  - **Previously generated `.docx` files:** re-run `md2docx.py` for proper tables and
    numbered lists. Lines like `1. item` used to come out as plain paragraphs; they're now
    Word-numbered.
- **Verify:**
  - `/wag:adr` pre-flight passes the item.
  - Every image line in the PRD resolves to a PNG in `.wag/mockups/screens/` (the
    script's printed lines match).
  - `PRD.docx` opens with a picture under every route.
