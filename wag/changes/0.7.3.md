# 0.7.3 — Mockups: dark first, then a designed light mode

**From:** 0.7.2
**Date:** 2026-10-28

Almost every WAG web app has a light/dark toggle, and the house UI standard wants both modes
designed, not one derived from the other. The mockup step treated colour as one thing. Now it
settles the look in dark mode, then designs light mode for the chosen look on purpose.

## What changed

In `/wag:poc` Step 3 (`wag/workflows/poc.md`):

- **Round one is dark only.** Every option is built in dark mode (`dark` on `<html>`, the
  `.dark` colour block).
- **After the pick, light mode is designed** with the user in the same file. The `:root`
  colour block is filled in alongside `.dark`, and a working light/dark toggle (the starter's
  `toggle-theme`) is added. It's the only working control in a mockup.
- **The finished mockup is one file** with both modes and the toggle. Step 3 ends when the
  user approves the look in both modes.
- **Step 4** writes the chosen mockup's `:root` and `.dark` blocks to `theme.css` as they
  stand.

## Reconcile a 0.7.2 project

- **Detect:** `wag_version` < 0.7.3, mid-POC, with a chosen mockup that has only one mode.
- **Reconcile:** before Step 4, design the chosen mockup's missing mode and add the toggle,
  in the same file. Keep its `.html.md` copy current.
- **Verify:** the chosen mockup switches cleanly between light and dark, and `theme.css` holds
  both blocks.
